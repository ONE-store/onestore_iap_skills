# 진단 — "안 된다"에서 원인까지

**대부분의 질문에는 오류 코드가 없다.** "결제가 안 돼요" · "빌드가 안 돼요" 뿐이다. 이 파일은 그
상태에서 **무엇을 확보하고 무엇으로 가르는지**를 담는다. 응답 코드의 뜻 자체는 `sdk-context.md`의
응답 코드 표가 원본이다 — 여기 다시 적지 않는다.

> [!warning] 먼저 나눈다 — **내가 볼 수 있는 것과 없는 것**
> 코드·빌드·로그는 내가 직접 본다. **기기 상태·계정·개발자센터 설정은 볼 수 없다** — 물어야 한다.
> 그 구분을 먼저 하지 않으면, 코드를 아무리 읽어도 답이 안 나오는 것을 계속 읽게 된다.

## 0. 로그부터 확보한다

`adb logcat -s OneStoreIAP` 가 출력하는 것이 진단의 1차 자료다. **직접 실행할 수 있으면 직접 받는다.**

```bash
adb devices                                  # 기기가 붙어 있는지 먼저 본다
adb logcat -c && adb logcat -s OneStoreIAP   # 지우고 나서 재현하게 한다
```

- **기기가 안 붙어 있거나 명령을 실행할 수 없으면** 명령을 주고 **재현 절차까지 적어** 결과를 받는다
  — "앱을 켜고 상품을 누른 뒤 나온 것을 전부 붙여 주세요".
- **"로그가 안 나와요"도 결과다.** 아래 1번이 그 판독표다. 로그가 없다고 진단을 멈추지 않는다.
- 로그를 받기 전에 코드만 읽고 원인을 단정하지 않는다. 추정을 답으로 내면 사용자가 엉뚱한 곳을 고친다.

## 1. 로그가 한 줄도 안 나올 때

**가장 흔하고, 가장 자주 오진되는 상태다.** 결제 코드가 아니라 **결제 코드가 실행되지 않는 것**이
원인이다. 위에서부터 확인한다.

| 확인 | 어떻게 보나 | 맞으면 |
|---|---|---|
| **매니저가 생성·시작되는가** | 액티비티에서 `start()` 호출을 찾는다 | 없으면 이것이 원인이다. 생명주기 연결(SKILL의 3단계 표)을 붙인다 |
| **릴리즈 빌드로 돌리고 있는가** | 설치된 것이 debug 빌드인지 | 진행 로그는 `debuggable` 일 때만 나온다. 경고·오류는 릴리즈에도 남으므로 **`-s OneStoreIAP` 에 아무것도 없으면 코드가 아예 안 도는 것**이다 |
| **태그를 맞게 걸었는가** | `adb logcat -s OneStoreIAP` 철자 | 필터를 빼고 `adb logcat \| grep -i onestore` 로 한 번 더 본다 |
| **앱이 그 기기에서 도는가** | 여러 기기·에뮬레이터가 붙어 있는지 | `adb devices` 가 둘 이상이면 `-s <시리얼>` 로 지정한다 |

**`not started — call start() first` 경고가 보이면** 매니저는 배치됐는데 생명주기 연결이 빠진 것이다.
이 한 줄이 곧 답이다.

## 2. 로그가 나올 때 — 어디서 멈췄는지로 가른다

로그는 순서대로 나온다. **마지막으로 찍힌 줄이 어디까지 갔는지**를 말해 준다.

| 마지막으로 보이는 것 | 멈춘 지점 | 볼 것 |
|---|---|---|
| `start:` 만 있고 `connecting...` 없음 | 클라이언트 생성 직후 | 공개키(`OneStoreLicenseKey.get()`)에서 예외가 났는지 — 값이 비면 던진다 |
| `connecting...` 에서 멈춤 | 서비스 연결 | 매니페스트 `<queries>` 누락 · 원스토어 앱 미설치. 함께 찍힌 `iap error code=` 를 응답 코드 표로 읽는다 |
| `connected` 후 `no products for …` | 상품 조회 | **오류가 아니다.** 상품 ID 오타 · 개발자센터 미등록 · 판매중 아님. 셋 다 코드로는 알 수 없으므로 **묻는다** |
| `products loaded:` 까지 정상, 구매를 눌러도 조용함 | 결제 요청 전 | 화면이 `launchPurchase` 를 부르는지. `launchPurchase:` 가 없으면 UI 쪽이다 |
| `launchPurchase:` 후 `onPurchasesUpdated` 없음 | 결제창 | **결제창이 떴는지 묻는다.** 안 떴으면 연결·`<queries>`, 떴으면 계정·테스트 ID·스토어 환경 |
| `onPurchasesUpdated: code=N` | 결제 결과 | `N` 을 응답 코드 표로 읽는다. `code=1` 은 사용자 취소이므로 오류가 아니다 |
| `handlePurchase:` 후 `consumed`/`acknowledged` 없음 | 후처리 | 함께 찍힌 `iap error code=` 를 본다. **3일 규칙에 걸리는 자리라 가장 급하다** |

### 로그가 곧 답인 세 줄

| 로그 | 뜻 |
|---|---|
| `handlePurchase: … consumable=false` 인데 재구매가 안 된다 | 소비성 지정이 빠졌다. `CONSUMABLE_PRODUCT_IDS` 를 본다 |
| `handlePurchase: … type=unknown` | 상품 조회 전에 구매가 들어왔다. 승인은 되므로 환불되지는 않는다 |
| `onResumed: skipped — …` | 회수가 안 돌았다. 이유가 그 줄에 있다 |

## 3. 빌드가 안 될 때

**먼저 `references/build-env.md` 로 가른다** — 자바(JDK) 문제면 배치한 코드와 무관하고, 그것이
빌드 실패의 대부분이다. 아래는 **배치한 코드 때문에 나는** 것들이다.

| 오류 | 원인 | 고치는 법 |
|---|---|---|
| `Unresolved reference: OneStoreLicenseKey` | 매니저만 배치하고 키 파일을 빼먹었다 | `license-key.kt.txt` 를 **같은 패키지**에 배치한다 |
| `Unresolved reference: com.gaa.sdk…` | 의존성이 없거나 다른 모듈에 있다 | `dependencies.md` 대로 **매니저를 넣은 모듈**에 넣는다. 저장소에 `mavenCentral()` 이 있는지도 본다 |
| 매니저의 `package` 가 디렉토리와 다르다 | 치환한 패키지와 배치 위치가 어긋났다 | 파일 첫 줄의 패키지와 실제 경로를 맞춘다 |
| `Unresolved reference: androidx.compose…` (테스트 화면) | Compose 프로젝트가 아니다 | 화면을 지운다. Compose 도입은 이 스킬의 범위가 아니다 |
| `@Composable invocations can only…` (테스트 화면) | Compose 컴파일러 설정이 없다 | 위와 같다 |

**빌드는 직접 돌려 확인한다.** 실행할 수 있으면 프로젝트의 빌드 명령으로 재현하고 **실제 오류 문구를
근거로 삼는다.** 못 하면 오류 전문을 받는다 — 요약된 한 줄로는 위 표에서 가를 수 없다.

## 4. 코드로는 절대 알 수 없는 것 — 물어야 한다

읽어서 확인할 수 없는 것들이다. **추정하지 않고 묻는다**(기본 규칙 4번). 로그의 응답 코드가 이쪽을
가리키면 여기서 멈추고 확인을 받는다.

| 물을 것 | 왜 필요한가 |
|---|---|
| 원스토어 앱이 설치·업데이트돼 있는가 | 없으면 연결 자체가 성립하지 않는다 (`RESULT_NEED_UPDATE`) |
| 원스토어에 로그인돼 있는가 | 구매 내역은 계정에 딸려 있다 (`RESULT_NEED_LOGIN`) |
| **테스트 ID로 등록된 계정인가** | 등록되지 않은 계정은 **상용 환경에서 실제로 과금된다** |
| 개발자센터에 상품이 등록되고 **판매중**인가 | 아니면 조회가 빈 목록이거나 `RESULT_ITEM_UNAVAILABLE` |
| 상품 ID가 정확히 무엇인가 | 대소문자·오타는 코드로 검증할 방법이 없다 |
| 결제창이 떴는가 | 연결 성공 여부를 가르는 가장 빠른 질문이다 |

## 답하는 형식

**원인 · 재현 조건 · 수정(코드 포함) · 참고 문서** 넷으로 답한다. 그리고 **근거를 로그 줄로 인용한다**
— "로그에 `no products for …` 가 있으므로 연결은 성공했고 상품 등록이 원인입니다"처럼, 어느 줄에서
그 판정이 나왔는지 보이게 한다. 근거 없이 결론만 적으면 사용자가 확인할 방법이 없다.
