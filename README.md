# ONE Store IAP Skill

**한국어** | [English](README.en.md)

> 원스토어 인앱결제(IAP) SDK 연동을 AI 코딩 에이전트가 돕게 하는 Agent Skill

![sdk-iap](https://img.shields.io/badge/sdk--iap-21.04.00-blue)
![Agent Skills](https://img.shields.io/badge/Agent%20Skills-open%20standard-brightgreen)
![platform](https://img.shields.io/badge/platform-Android-green)

설치해 두면 AI 코딩 에이전트가 원스토어 인앱결제 SDK를 이해한 상태로 **의존성 추가 · 매니페스트 설정
· 결제 코드 배치 · 동작 확인 화면 · 오류 진단 · 릴리즈 전 점검**을 도와줍니다.

평소 쓰던 말로 요청하면 되고, 스킬 이름을 부를 필요는 없습니다. Agent Skills는
[개방 표준](https://agentskills.io)이라 **하나의 번들이 여러 AI 코딩 도구에서 그대로 동작합니다.**

```text
나: 원스토어 인앱결제 붙여줘

에이전트: 의존성과 <queries>를 추가하고 결제 매니저를 배치했습니다.
          다음 값 세 개가 필요합니다 — 아래 틀을 복사해 채워 주세요.
          공개키: (여기에 붙여 넣어 주세요)
                  개발자센터 → 공통정보 → 라이선스 관리에서 ...
```

## 주요 기능

| 기능 | 설명 |
|---|---|
| **상태 진단** | 프로젝트를 읽어 무엇이 되어 있고 무엇이 빠졌는지 표로 알려줍니다. 이 단계는 **파일을 고치지 않습니다** |
| **의존성 추가** | Version Catalog · Kotlin DSL · Groovy DSL 중 프로젝트에 맞는 방식으로 |
| **매니페스트 설정** | `<queries>`와 INTERNET 권한 — 빠뜨리면 Android 11 이상에서 연결이 실패합니다 |
| **결제 코드 배치** | 검증된 매니저 클래스를 프로젝트 패키지에 맞춰 배치합니다. 라이선스 공개키를 평문 상수로 두지 않습니다 |
| **값 채우기** | 공개키 · 상품 ID · **어떤 상품이 소비성인지**를 앱 사정에 맞게 |
| **동작 확인 화면** | 로그인 · 상품 목록 · 구매 · 소비/승인을 눌러서 확인하는 화면 (Compose 프로젝트 전용) |
| **오류 진단** | 응답 코드를 원인 · 재현 조건 · 수정 코드 · 참고 문서로 풀어 줍니다. 오류 코드 없이 "결제가 안 된다"만 있어도 로그부터 확보해 진단합니다 |
| **릴리즈 전 점검** | 실제로 사고가 나는 항목을 훑고, 출시를 막아야 할 것은 블로커로 따로 모아 줍니다 |

## 시작하기

### 요구 사항

| 항목 | 내용 |
|---|---|
| 안드로이드 프로젝트 | Gradle 프로젝트. **기존 `compileSdk`·`minSdk`·Java 타깃을 바꾸지 않습니다** |
| AI 코딩 도구 | Agent Skills를 읽는 도구 하나 ([지원 도구](#지원-도구) 참고) |
| 원스토어 개발자센터 | 계정과 **등록된 인앱 상품**. 상품이 없으면 조회가 빈 목록으로 옵니다 |
| Jetpack Compose | **동작 확인 화면에만** 필요합니다. 나머지 기능은 Compose가 없어도 됩니다 |
| 셸 | 설치 스크립트는 bash입니다 — macOS · Linux, Windows는 WSL이나 Git Bash. 스크립트 없이 [직접 복사](#설치)해도 됩니다 |

### 설치

```bash
git clone https://github.com/ONE-store/onestore_iap_skills.git
cd onestore_iap_skills
./install.sh <안드로이드_프로젝트_경로>
```

`.claude/skills/` · `.agents/skills/` · `.grok/skills/` 세 곳에 설치합니다. 이 셋이면 아래 도구를
대부분 덮습니다.

**옵션**

| 옵션 | 하는 일 |
|---|---|
| `--dry-run` | 무엇을 어디에 복사할지만 보여주고 아무것도 바꾸지 않습니다 |
| `--user` | 홈 디렉토리에 설치해 **모든 프로젝트**에서 쓰게 합니다 |
| `--all` | `.cursor/` · `.github/` · `.gemini/` · `.codex/` · `.junie/` 까지 함께 설치합니다 |
| `--pull` | 원격에서 최신을 받아온 뒤 설치합니다 |
| `--force` | 설치본을 직접 고쳤더라도 덮어씁니다 |
| `--offline` | 원격 확인을 건너뜁니다 |

**직접 복사**해도 됩니다. 쓰는 도구의 경로에 `skills/onestore-iap` 폴더를 그대로 넣으면 됩니다.

```bash
cp -R skills/onestore-iap <프로젝트>/.claude/skills/
```

### 지원 도구

| 도구 | 프로젝트 스킬 경로 |
|---|---|
| Claude Code | `.claude/skills/` |
| Cursor | `.agents/skills/` · `.cursor/skills/` (`.claude/` · `.codex/` 도 읽습니다) |
| GitHub Copilot / VS Code | `.github/skills/` · `.claude/skills/` · `.agents/skills/` |
| Gemini CLI | `.gemini/skills/` · `.agents/skills/` |
| OpenAI Codex | `.agents/skills/` |
| Grok Build | `.grok/skills/` — **프로젝트에서는 `.agents/skills/` 를 읽지 않습니다** |
| Junie (JetBrains) | `.junie/skills/` — `--all` 로 설치합니다 |

개인 설정으로 쓰려면 홈 디렉토리 아래 같은 경로(`~/.claude/skills/` 등)에 두세요.

### 업데이트

같은 명령을 다시 실행하면 **바뀐 것만 갱신**합니다. 설치 전에 원격을 확인해 로컬 사본이 뒤처졌으면
알려주고, `--pull` 을 주면 받아온 뒤 설치합니다.

```bash
./install.sh --pull <안드로이드_프로젝트_경로>
```

**설치본을 직접 고쳤다면 덮어쓰지 않고 멈춥니다.** 설치할 때 남긴 파일별 체크섬으로 "원본이
새로워서 다른 것"과 "직접 고쳐서 다른 것"을 구분합니다. 덮어쓰려면 `--force` 를 주세요.

## 사용법

설치한 뒤 그 프로젝트에서 AI 코딩 도구를 열고 평소처럼 물어보면 됩니다.

```text
원스토어 인앱결제 붙여줘
지금 원스토어 결제 설정이 어디까지 됐어?
상품은 코인 3종이고 광고 제거 상품도 있어. 값 채워줘
잘 붙었는지 눌러보고 싶어. 테스트 화면 추가해줘
구매하면 responseCode 7이 떨어지는데 왜 그래?
결제가 안 되는데 로그 어떻게 봐?
릴리즈 전에 결제 부분 점검해줘
```

| 막혔을 때 이렇게 물으세요 | 무엇이 나오나 |
|---|---|
| **"원스토어 결제 스킬로 뭘 할 수 있어?"** | 할 수 있는 일을 알려주고 곧바로 현재 상태를 진단합니다 |
| **"이제 뭐 해야 해?"** | 지금 상태를 다시 읽고 다음 단계와 **무엇을 요청하면 되는지**까지 알려줍니다 |

### 미리 준비할 것

연동을 끝내려면 값 셋이 필요합니다. 없어도 코드 배치까지는 진행되고, 값 자리는 비워 둔 채로
멈춥니다.

| 값 | 어디서 |
|---|---|
| **라이선스 공개키** | 개발자센터 → 공통정보 → 라이선스 관리 |
| **상품 ID 목록** | 개발자센터 → In-App 정보에 등록한 `In-App ID` |
| **그중 무엇이 소비성인지** | 앱 기획 — 다시 살 수 있어야 하는 상품이 어느 것인지 |

세 번째는 코드로 알 수 없어서 반드시 물어봅니다. 코인·아이템처럼 쓰면 없어지는 것이 소비성이고,
광고 제거·프리미엄 해제처럼 한 번 사면 끝인 것은 아닙니다. **잘못 고르면 오류 없이 조용히
깨집니다** — 영구성 상품을 소비하면 사용자가 그 상품을 다시 구매할 수 있게 됩니다.

### 언어 지원

한국어와 영어로 편하게 물어보세요. 다른 언어로 물어도 그 언어로 답하도록 되어 있습니다.

에이전트가 어떤 언어로 답하든, 개발자센터에서 찾아야 하는 메뉴는 실제 화면에 보이는 한국어
이름을 함께 알려드립니다.

## 주의 사항

> [!IMPORTANT]
> **결제 코드는 조용히 깨집니다.** 컴파일이 되고 화면이 떠도 상품이 지급되지 않거나 환불될 수
> 있습니다. 이 스킬은 확인 수단과 점검 항목을 함께 제공하지만, **최종 확인은 개발자 몫입니다.**

- **생성·수정된 코드를 읽어 보세요.** 특히 상품 지급 로직과 소비/승인 분기입니다
- **샌드박스 테스트를 반드시 거치세요.** 개발자센터에서 **테스트 ID를 등록**하지 않은 계정으로
  상용 환경에서 구매를 누르면 **실제로 과금됩니다**
- **구매 후 3일 안에 소비 또는 승인해야 합니다.** 하지 않으면 미지급으로 판단해 자동 환불됩니다.
  스킬이 배치하는 코드는 이것을 자동으로 처리하지만, **동작 확인 화면만 예외**로 직접 눌러 보도록
  꺼 둡니다 — 그 화면을 그대로 운영에 쓰지 마세요
- **릴리즈 전에 점검을 한 번 돌리세요.** 위 항목들을 코드에서 다시 확인합니다

## 스킬이 하지 않는 것

- **Gradle 동기화와 빌드** — 의존성을 추가한 뒤 동기화는 직접 하셔야 합니다
- **실제 결제 테스트** — 샌드박스 테스트와 테스트 ID 등록은 개발자센터에서 하는 일입니다
- **서버 영수증 검증 구현** — 서버 대 서버 검증은 앱이 할 수 없는 일입니다. 서버가 상품을 지급하는
  구조라면 코드에 연결 지점만 만들고, 서버 쪽은 개발사 몫입니다. **구매 서명은 공개키를 넘긴 것으로
  SDK가 이미 검증합니다**
- **동작 확인 화면을 운영 화면으로 고치기** — 확인용 화면이라 거기까지만 합니다. 운영 화면은 앱의
  디자인·지급 로직에 맞춰 직접 만드시면 됩니다
- **프로젝트의 빌드 설정 변경** — `compileSdk` · `minSdk` · Java 타깃을 샘플 값에 맞춰 올리지 않습니다
- **진입 화면을 임의로 변경** — 확인 화면을 배치한 뒤 **연결해 줄지 물어봅니다.** 해달라고 하시면
  진입 화면을 건드리지 않는 방법(별도 액티비티)부터 제시합니다

## 구성

```text
install.sh                        # 스킬을 프로젝트·홈 디렉토리에 설치
skills/onestore-iap/
├── SKILL.md                      # 진입점 — 절차와 판단 기준
└── references/
    ├── sdk-context.md            # API · 호출 순서 · 상품 타입 · 응답 코드 전체 · 공개키
    ├── dependencies.md           # 의존성 추가 세 경로
    ├── manifest-queries.xml.txt  # <queries> · 권한 · 개발 옵션
    ├── purchase-manager.kt.txt   # 결제 매니저 (패키지 자리는 플레이스홀더)
    ├── license-key.kt.txt        # 공개키 제공 (평문 상수를 쓰지 않습니다)
    ├── license-manager.kt.txt    # 라이선스 검증 매니저 (유료 앱 전용)
    ├── test-screen.kt.txt        # 동작 확인용 Compose 화면
    ├── checks.md                 # 상태 진단 · 릴리즈 점검 항목
    ├── build-env.md              # 자바(JDK) 설정 때문에 빌드가 안 될 때
    └── diagnose.md               # "안 되는데 왜 그런지 모르겠다" 를 받았을 때
```

`SKILL.md` 는 절차와 판단 기준만 담고, 사실과 코드 원문은 `references/` 에 둡니다. 에이전트는 그때
필요한 파일만 읽습니다.

## 커스터마이징

번들은 마크다운과 텍스트 파일이라 그대로 열어 고칠 수 있습니다. 앱 사정에 맞게 절차나 코드 원문을
바꿔 쓰셔도 됩니다.

> [!WARNING]
> **매니저 클래스의 소비/승인 분기와 연결 보장 함수는 유지하시는 편이 좋습니다.** 없애면 3일 규칙
> 때문에 결제가 환불되거나, 서비스 연결이 끊긴 뒤 호출이 간헐적으로 실패합니다.

설치본을 고치는 대신 **이 저장소 사본을 고친 뒤 설치**하시면 다음 업데이트에서 같은 선택을 반복하지
않습니다.

## 문제 해결

<details>
<summary><b>에이전트가 스킬을 쓰지 않습니다</b></summary>

먼저 스킬이 보이는지 확인하세요 — **"지금 사용할 수 있는 스킬을 나열해줘"** 라고 물어봅니다.

- **목록에 없다** → 설치 경로 문제입니다. 쓰는 도구가 읽는 경로가 맞는지 [지원 도구](#지원-도구)
  표에서 확인하고, 설치한 뒤 **세션을 새로 시작**하세요
- **목록에는 있는데 쓰지 않는다** → 요청에 "원스토어"나 "인앱결제" 같은 말을 넣어 보세요.
  그래도 직접 코드를 만들려고 하면 **"스킬을 써서 해줘"** 라고 덧붙이면 됩니다

</details>

<details>
<summary><b>빌드가 안 됩니다</b></summary>

**대부분 결제 코드 문제가 아니라 자바(JDK) 설정입니다.** 특히 IDE로 만든 프로젝트를 터미널에서
빌드할 때 갈립니다. 아래 메시지가 보이면 그쪽입니다.

- `Unsupported class file major version`
- `Android Gradle plugin requires Java …`
- `JAVA_HOME is not set`

에이전트에게 오류 전문을 그대로 주면 원인과 고치는 방법을 알려줍니다. 결제 코드 때문에 나는
빌드 오류(키 파일 누락 · 의존성 모듈 불일치 등)도 함께 가려 줍니다.

</details>

<details>
<summary><b>결제가 안 되는데 원인을 모르겠습니다</b></summary>

배치된 코드는 디버그 빌드에서 진행 상황을 `OneStoreIAP` 태그로 남깁니다.

```bash
adb logcat -s OneStoreIAP
```

연결 · 상품 조회 결과 · 결제 요청과 결과 · 소비/승인 분기가 순서대로 찍히므로, **마지막으로 찍힌
줄이 어디까지 갔는지**를 말해 줍니다. 그 출력을 에이전트에게 그대로 주면 됩니다.

**로그가 한 줄도 안 나오는 것도 단서입니다** — 결제 코드가 아예 실행되지 않고 있다는 뜻이고,
대개 액티비티에서 매니저를 시작하지 않은 경우입니다.

</details>

<details>
<summary><b>상품 목록이 비어서 옵니다</b></summary>

오류가 아니라 조회 결과가 없는 것입니다. 셋 중 하나입니다.

1. 개발자센터에 상품이 등록되지 않았다
2. 코드의 상품 ID와 등록한 `In-App ID` 가 **글자 그대로** 같지 않다
3. 상품이 판매중 상태가 아니다

세 가지 모두 코드로는 확인할 수 없어 에이전트가 물어봅니다.

</details>

<details>
<summary><b>구매했는데 다시 구매할 수 없습니다 (responseCode 7)</b></summary>

`RESULT_ITEM_ALREADY_OWNED` 입니다. **소비성 상품인데 소비하지 않은 경우**가 대부분입니다.

다만 **영구성 상품이나 구독에서 이 코드가 나오는 것은 정상**입니다 — 이미 가지고 있다는 뜻이라
고칠 것이 없습니다. 어느 쪽인지는 그 상품이 소비성인지에 달렸습니다.

</details>
